# ADR-001: Modular monolith with vertical slices

Date: 2026-07-27
Status: Accepted

## Context

The platform targets 5–8 microservices eventually (see docs/00-overview.md), but
development starts with one Spring Boot app and no domain logic yet. Starting with
separate microservices would add Kafka, service discovery, and deployment complexity
before any business rules exist. Starting with a classic layered monolith (one big
`controllers/`, `services/`, `repositories/`) would tangle bounded contexts together
and make later extraction painful.

## Decision

Build a **modular monolith**: one Spring Boot app, one Maven module, base package
`com.bankapp`. Each bounded context (auth, accounts, payments, frauddetection,
notifications, reports) is a top-level package — a vertical slice — containing its
own horizontal layers (`api`, `application`, `domain`, `infrastructure`).

Boundary rules (documented in docs/08-system-architecture.md):

- Slices communicate via domain events or application-service interfaces only —
  never by importing another slice's entities or repositories.
- Inside a slice: `api → application → domain ← infrastructure`; the domain layer
  has no framework imports.
- `shared/` is a small shared kernel (value objects, base types, cross-cutting
  config), not a dumping ground.

The base package was renamed from `com.bank_app.bank_app` (Spring Initializr
artifact of the hyphenated groupId `com.bank-app`) to `com.bankapp` while the
project had only two classes.

## Consequences

- One process, one database, one deploy — fast local dev and refactoring while the
  domain model is still being discovered.
- Package boundaries mimic service boundaries, so extracting a slice into its own
  microservice later means lifting one top-level package into a new app, replacing
  in-process events with Kafka topics.
- Boundary discipline is by convention until ArchUnit tests are added to enforce
  the import rules.
- CQRS/event-driven patterns can be introduced per-slice (e.g. payments → fraud
  detection) without a distributed system tax up front.
